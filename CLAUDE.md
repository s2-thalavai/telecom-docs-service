# CLAUDE.md

Context for Claude Code (and other AI assistants) working in this repository.

## What this is

`telecom-docs-service` is a Spring Boot 3.5 / Java 21 Telecom Customer API (plans, customers v1/v2, HTTP Basic
with AGENT/ADMIN roles) whose **API reference is generated by Spring REST Docs**. The documentation is a build
artifact and is part of the definition of done: **an API change without matching documentation must fail the build.**

## Commands

| Task | Command |
|---|---|
| Tests (unit + documentation) | `make test` |
| Build the HTML docs | `make docs` → `target/generated-docs/index.html` |
| Everything | `make verify` |
| Run (H2) | `make run` → `/docs/index.html` |
| Compose (MySQL) | `make up`, `make smoke` |
| Optional OpenAPI/Swagger UI | `make openapi` (see docs/openapi-integration.md) |

Run `make verify` before finishing. It is the only command that runs the coverage and served-docs checks.

## How the docs are built

`*DocumentationTest` (MockMvc + `document(id, ...)`) → `target/generated-snippets/<id>/*.adoc`
→ `src/main/asciidoc/*.adoc` include them with `operation::<id>[snippets='...']`
→ asciidoctor-maven-plugin (`prepare-package`, **failIf WARN**) → `target/generated-docs`
→ copied to `target/classes/static/docs` → packaged → served at `/docs/**` (public in `SecurityConfig`).

Because of this, **never build with `-DskipTests`** unless you also pass `-Dasciidoctor.skip=true`. Without the tests there are no snippets, and Asciidoctor fails. The Dockerfile runs the tests on purpose.

## Changing the API

Follow `docs/writing-docs.md`. In short: every new endpoint needs a documentation test (enforced by
`ApiDocumentationCoverageIT`) and an `operation::` entry in the prose (an operation that is referenced but not generated fails Asciidoctor).
Field changes break the strict `responseFields`/`requestFields` descriptors. Fix the descriptor in the same change,
not by switching to `relaxed*`.

## Conventions

- Documentation tests use **mocked services and fixed data** (`ApiDocs`) for stable examples. Behaviour against the real stack is covered by `CustomerApiIT`.
- Shared descriptors live in `ApiDocs`, request-field constraints come from `ConstrainedFields`, and global preprocessors live in `RestDocsConfiguration`.
- `MaskAuthorizationHeader` must keep the Basic placeholder **valid Base64**, because the curl and HTTPie snippets decode it.
- Every error is a ProblemDetail (`GlobalExceptionHandler extends ResponseEntityExceptionHandler`; the security handlers in `SecurityConfig`). The `problem()` descriptor relies on `instance` always being set.
- Identifiers: `{resource}-{action}`, `error-{kind}`, `v2/...` for version 2.
- Prod schema: Flyway (`db/migration`). Entity changes need a new migration (`MySqlFlywayIT`).

## Don'ts

- Don't put real credentials in docs tests' expectations, fixtures or prose. `DocsServedIT` checks the served HTML.
- Don't add documentation annotations (Swagger) to controllers. OpenAPI comes from tests (`-Popenapi`).
- Don't reorder the asciidoctor and resources plugins in `pom.xml`. Rendering must happen before copying.
